## 1. 总结论

结论：**接口契约校准已经做过一轮，但还没有完全完成。**

当前状态可以判断为：

```text
不是“没有实现”
```

- 当前最需要做的是：**收尾式接口契约修复**，而不是重新做一遍接口设计。

## 3. 当前仍未完全对齐的问题

## P0-1：前端使用 `/api` baseURL，但 `vite.config.ts` 未配置代理

### 现状

前端 `src/api/request.ts`：

```ts
baseURL: '/api'
```

但 `vite.config.ts` 当前只有：

```ts
plugins: [vue()],
resolve: { alias: { '@': ... } }
```

没有配置：

```ts
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true
    }
  }
}
```

### 影响

本地开发时，前端请求会先打到 Vite 开发服务器。

如果没有代理，就容易出现：

```text
页面正常显示，但接口没打到后端
404
网络请求失败
退出登录、后台接口、上传接口无反应
```

### 建议修复

在 `ai-knowledge-vue/vite.config.ts` 中增加：

```ts
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
    },
  },
},
```

如果后端已经设置了 `server.servlet.context-path=/api`，则不要 rewrite。

如果后端没有 context-path，而 Controller 直接从 `/auth`、`/documents` 开始，则需要 rewrite：

```ts
rewrite: path => path.replace(/^\/api/, '')
```

当前 README 写的是后端 Base URL 为 `http://localhost:8080/api`，所以更可能是后端已有 `/api` 上下文，优先不 rewrite。

## P0-2：前台文档列表接口参数不一致

### 前端

```ts
getDocumentPage(params: {
  knowledgeBaseId?: number
  keyword?: string
  parseStatus?: string
  embeddingStatus?: string
  pageNo?: number
  pageSize?: number
})
```

### 后端

`DocumentController#page`：

```java
@GetMapping
public ApiResponse<PageResponse<DocumentVO>> page(
  @RequestParam Long knowledgeBaseId,
  @RequestParam(defaultValue = "") String keyword,
  @RequestParam(defaultValue = "1") int pageNo,
  @RequestParam(defaultValue = "10") int pageSize
)
```

### 问题

- 前端 `knowledgeBaseId` 是可选；后端 `knowledgeBaseId` 必传。
- 前端传 `parseStatus`、`embeddingStatus`；后端不接收。

### 影响

如果前端“文档管理页”要展示当前用户全部文档，但没有传 `knowledgeBaseId`，后端会报参数缺失。

如果前端页面提供解析状态、向量状态筛选，后端目前不会生效。

### 建议修复

推荐后端改成：

```java
@GetMapping
public ApiResponse<PageResponse<DocumentVO>> page(
  @RequestParam(required = false) Long knowledgeBaseId,
  @RequestParam(defaultValue = "") String keyword,
  @RequestParam(required = false) String parseStatus,
  @RequestParam(required = false) String embeddingStatus,
  @RequestParam(defaultValue = "1") int pageNo,
  @RequestParam(defaultValue = "10") int pageSize
)
```

业务规则：

```text
knowledgeBaseId 有值：查询该知识库下文档
knowledgeBaseId 为空：查询当前用户全部文档
parseStatus 有值：按解析状态筛选
embeddingStatus 有值：按向量状态筛选
```

```ts
retryDocumentTask(id: number) {
```

### 后端


### 建议修复
